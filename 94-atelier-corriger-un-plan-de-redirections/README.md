# Atelier : corriger un plan de redirections

RAPPEL THÉORIQUE Une redirection est une instruction envoyée par le serveur pour rediriger un utilisateur (et les robots des moteurs de recherche) d'une URL vers une autre. La redirection 301 signifie « déplacé de façon permanente » : elle transfère l'essentiel de la valeur SEO (link equity) vers la nouvelle URL. La redirection 302 signifie « temporaire » et ne transfère pas durablement cette valeur. Le mental model à retenir : chaque URL supprimée, déplacée ou renommée doit pointer vers l'URL la plus pertinente possible, en une seule étape, avec le bon code HTTP. Les erreurs fréquentes sont nombreuses : utiliser une 302 là où une 301 s'impose, créer des chaînes de redirections (URL A → B → C → D) qui ralentissent le crawl et diluent la valeur, produire des boucles de redirection (A → B → A) qui rendent la page inaccessible, rediriger massivement vers la page d'accueil au lieu d'une page équivalente (mauvais signal appelé « soft 404 »), ou encore oublier de rediriger une ancienne URL, laissant une erreur 404. Mini-exemple : le site migre de HTTP vers HTTPS. L'URL http://site.fr/blog/article-a doit être redirigée en 301 directement vers https://site.fr/blog/article-a. Si à la place on trouve http → http (avec www) → https, on a une chaîne à corriger pour ne conserver qu'un seul saut.
