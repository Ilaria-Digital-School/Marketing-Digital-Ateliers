# Atelier : manipuler robots.txt et sitemap sur un bac à sable

RAPPEL THÉORIQUE Le fichier robots.txt est un fichier texte placé à la racine d'un site (ex : https://monsite.com/robots.txt). Il donne aux robots d'exploration (crawlers) des directives sur ce qu'ils peuvent ou ne peuvent pas explorer. Le mental model à retenir : robots.txt gère le CRAWL (l'accès), pas l'INDEXATION (la présence dans les résultats). Une page bloquée par robots.txt peut malgré tout apparaître dans Google si elle est liée ailleurs — pour empêcher l'indexation, on utilise la balise meta robots noindex, pas robots.txt. Le sitemap.xml est à l'inverse une invitation : il liste les URL que vous souhaitez voir explorées et indexées, avec des métadonnées (date de modification, priorité). Il facilite la découverte des pages, surtout sur les gros sites ou les sites peu maillés. Les directives clés du robots.txt sont : User-agent (à quel robot on s'adresse), Disallow (interdire un chemin), Allow (autoriser une exception) et Sitemap (indiquer l'emplacement du sitemap). Erreurs fréquentes : bloquer par erreur tout le site avec Disallow: / ; croire que robots.txt masque une page des résultats ; oublier le / final ou mal orthographier les chemins ; référencer dans le sitemap des URL bloquées ou en noindex (signaux contradictoires). Mini-exemple : User-agent: * Disallow: /admin/ Allow: /admin/public/ Sitemap: https://monsite.com/sitemap.xml Ici, tous les robots sont bloqués sur /admin/ sauf /admin/public/, et le sitemap est signalé. --- ÉNONCÉ DE L'ATELIER Cet atelier vous met en situation réelle : vous allez créer, éditer et valider un fichier robots.txt et un sitemap.xml sur un environnement bac à sable...
